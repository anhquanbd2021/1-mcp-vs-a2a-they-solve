How the lab reads a hop.

The lab simulates one incident task — why did checkout p95 latency spike at 14:00? — moving through a toy agent stack. Every hop is tagged by the boundary it crosses, so each failure reads as a layer problem, not "the agent protocol broke."

The two boundaries

layerboundaryops in this labwhat it standardizes
a2aagent ↔ agent — the seamagents/discover (agent cards), tasks/send, tasks/resultWho can take work: skills, task lifecycle (submitted → working → completed/failed), artifacts coming back across a trust boundary.
mcpagent ↔ tool — the edgetools/list, tools/callWhat an agent can use: tool discovery, input schemas, invocation. The model stays in control — the protocol is a socket, not a manager.
tasklifecycle eventstask.submit, state, tasks/aggregateNot a protocol — the run bookkeeping so the trace reads top to bottom.

The three failures — one per concept

  • dead MCP server (metrics-db down): the tools/list call never answers, so tools/call never fires. The A2A hops all succeed — the coordination layer held; the capability vanished. Verdict: degraded.
  • delegation loop: the metrics specialist can't map its subtask and delegates back to the orchestrator — which is already in the task's delegationPath. The router refuses the cycle with DELEGATION_LOOP. No MCP hop ever runs for that agent. Verdict: failed.
  • thin handoff: the A2A hop is healthy — the task is delivered — but the packet arrives without service/window. The specialist's tools/call goes out missing required arguments and the schema rejects it with INSUFFICIENT_CONTEXT. A content failure riding a healthy delegation. Verdict: degraded.

Reading the trace

  • Count failures by layer, not in total. A run with two failed mcp hops and clean a2a hops is a tool problem with healthy coordination — fix the server, not the topology.
  • A failed tasks/send is an A2A-leg problem — the work never reached a tool edge. In this lab that only happens via DELEGATION_LOOP.
  • A failed tools/call with reachable discovery is a content problem — the protocol delivered a task that carried too little.

Honest limits

  • Shapes, not wire formats. Ops are named and sequenced like real MCP (tools/list, tools/call, JSON-schema-shaped inputs) and A2A (agent cards, task lifecycle) calls, but nothing here speaks JSON-RPC or HTTP. Do not point a real client at it.
  • No model is ever called — the specialists' "reasoning" is a fixture that maps subtasks to tools.
  • Real A2A deployments add authentication between agent boundaries, streaming task updates, and long-running task states this lab compresses to a synchronous ladder.
  • Real MCP adds resources/prompts, transport negotiation (stdio vs. HTTP), and roots/elicitation — none modeled here.
  • One scenario, two specialists, one tool each. The point is the boundary, not the topology.

This is an educational demo, not production infrastructure.
